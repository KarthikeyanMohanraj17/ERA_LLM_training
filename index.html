Timeline
    A chronological tour of attention, 2017 → 2026

    How attention actually got here

    Every mechanism below is real, dated, and sourced — check the link at the top of each section if you don't believe a date. They're ordered by when they actually shipped, not by how a textbook would group them. Read it top to bottom and you'll see the field's actual priorities shift over time: first make attention work at all, then make decoding cheaper, then fix position, then make context longer, then bring recurrent state and sparsity back for the parts exact attention can no longer afford.

    baselineJun 2017

    Scaled dot-product attention

    Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin — Attention Is All You Need, arXiv:1706.03762 (Google Brain / Google Research / U. Toronto)

    Before this, a token's vector never learned anything about the other tokens around it. Every mechanism on this page is either this, or a response to a cost this introduced.

    Each token makes three projections of itself: a query ("what am I looking for?"), a key ("what do I contain?"), and a value ("what do I give you if you pick me?"). A token's query is compared against every other token's key with a dot product, the scores are scaled by 1/√d_k so they don't blow up, a causal mask zeroes out anything in the future, softmax turns what's left into weights that sum to 1, and those weights combine the values into one output vector.

    Interactive — step through a 6-token sequence
    Turn the mask off — attention weight immediately moves onto tokens that haven't happened yet. That's exactly the problem the causal mask exists to solve.
    Two bills this sends: compute grows roughly as T² (every token compares with every other token), and generation needs a growing KV cache — one saved key and value per earlier token, for every active conversation. Everything from here on is field working on one or both of those bills.
    01Jun 2017

    Sinusoidal positional encoding

    Same paper as above — Attention Is All You Need, arXiv:1706.03762

    Problem

    Self-attention is permutation-invariant — swap two tokens and the set of query/key/value comparisons doesn't change. Unlike an RNN, nothing in the mechanism itself knows which token came first.

    Fixed

    A fixed function PE(pos, 2i) = sin(pos / 10000^(2i/d)), PE(pos, 2i+1) = cos(...) is added to each token's embedding before the first layer — different positions get different, deterministic patterns.

    Cost

    A fixed, non-learned function — no adaptivity to the data, and despite the paper's hope that it would let the model "extrapolate to sequence lengths longer than the ones encountered during training," it empirically extrapolates poorly beyond the trained length.

    When to choose it

    Rarely chosen fresh today — but it's the reason later methods (RoPE especially) still think in terms of sinusoidal frequencies.

    02Jun 2018

    Absolute learned positional embeddings

    Radford, Narasimhan, Salimans, Sutskever (OpenAI) — Improving Language Understanding by Generative Pre-Training (GPT-1). Adopted a few months later by BERT (Devlin et al., arXiv:1810.04805, Oct 2018). Footnote: a learned position-embedding table appears even earlier, in a non-attention architecture — Gehring et al., Convolutional Sequence to Sequence Learning, May 2017.

    Problem

    Sinusoidal encoding imposes a fixed geometric prior. What if the useful positional structure for a given task isn't a clean sine wave?

    Fixed

    Replace the fixed function with a trained embedding table indexed by absolute position — max_position × d_model — trained end-to-end alongside the token embeddings. The model learns whatever positional pattern is useful.

    Cost

    A hard length ceiling. Position 4,097 in a table trained up to 4,096 simply doesn't exist — there's no function to fall back on, only an untrained (or missing) row.

    When to choose it

    When your maximum sequence length is known and fixed in advance, and you want the model to be free to learn non-uniform positional structure rather than impose one.

    Interactive — a computable function vs. a trained table
    The sinusoidal curve keeps going past the trained region because it's a formula. The learned table simply has nothing there.
    03Apr 2019

    Sparse Transformers

    Child, Gray, Radford, Sutskever (OpenAI) — Generating Long Sequences with Sparse Transformers, arXiv:1904.10509

    Problem

    Full self-attention over sequences of tens of thousands of steps (raw audio, high-resolution images) was intractable — O(n²) memory and compute.

    Fixed

    Factorize attention into two sparse patterns — strided (attend to every k-th earlier token) and local (attend to a nearby window) — whose union approximates full attention at O(n√n).

    Cost

    This is an approximation of full attention, not full attention. The sparsity patterns are hand-designed per data modality, and you typically need multiple heads/patterns to recover full-attention-level expressivity.

    When to choose it

    Very long, structurally regular sequences (images, audio) where a fixed geometric pattern is a reasonable prior for what should attend to what.

    Interactive — strided vs. local vs. their union (16 tokens, causal)
    04Nov 2019

    Multi-Query Attention (MQA)

    Shazeer (Google) — Fast Transformer Decoding: One Write-Head is All You Need, arXiv:1911.02150

    Problem

    During autoregressive decoding, every layer reloads its per-head K/V tensors from memory at every step. At generation time this is memory-bandwidth bound, not compute bound.

    Fixed

    All query heads keep their own projections, but share a single set of key/value projections. One K/V head instead of one per query head — far less to reload per step.

    Cost

    The paper reports this directly: "minor quality degradation" relative to full multi-head attention. One shared K/V head is a real bottleneck on representational diversity.

    When to choose it

    Decoding-latency-critical serving where the quality gap is acceptable — or as the extreme end of the GQA dial (see below), rather than a standalone choice.

    Interactive — 8 query heads, 1 shared key/value head
    05Apr 2020

    Sliding window attention — the origin: Longformer

    Beltagy, Peters, Cohan (Allen Institute for AI) — Longformer: The Long-Document Transformer, arXiv:2004.05150

    Problem

    Long-document tasks (classification, QA over full documents) need attention over thousands of tokens, but O(n²) full attention makes that expensive at encoder scale.

    Fixed

    Each token attends only within a local, fixed-size window — linear rather than quadratic scaling — plus task-specific global attention on a handful of special tokens (like [CLS]) that stay visible to and from everything.

    Cost

    A token outside the local window is invisible to a given layer directly; long-range dependencies have to propagate through several stacked layers instead of being read directly.

    When to choose it

    Encoder-style long-document tasks where a few designated tokens can carry the global summary role. This is the origin of the mechanism — the decoder/KV-cache framing below (Mistral, 2023) is a different, later application of the same idea.

    Interactive — local window + global tokens (green)
    06Jun 2020

    Linear attention

    Katharopoulos, Vyas, Pappas, Fleuret (EPFL / Idiap) — Transformers are RNNs: Fast Autoregressive Transformers with Linear Attention, arXiv:2006.16236, ICML 2020

    Problem

    Softmax ties every query's weights to the scores of every other key it's being compared against — you can't compute a key's contribution without knowing all the other keys. That ties the compute to O(T²) and rules out pre-summarizing the past.

    Fixed

    Replace softmax(QKᵀ)V with a kernel feature map φ(Q)φ(K)ᵀV. Because matrix multiplication associates, this can be computed as a running sum — a fixed-size state S = Σ φ(kⱼ)vⱼᵀ updated one token at a time, exactly like an RNN hidden state. Sequence-length cost drops from O(T²) to O(T).

    Cost

    The kernel feature map only approximates true softmax similarity — an expressiveness trade. And the entire past is compressed into one fixed-size matrix: different memories can interfere with each other, and there's no way to go back and read an individual old token exactly.

    When to choose it

    Very long sequences where O(T²) softmax attention is the actual bottleneck and some recall loss is acceptable — or as a building block inside a hybrid schedule (see LightningLM at the end of this timeline).

    The toy arithmetic below is the same one from Section 4 of the source lecture: q·k₁v₁ + q·k₂v₂ + q·k₃v₃ can be regrouped as q·(k₁v₁+k₂v₂+k₃v₃) — a fixed state S computed before the query even arrives. Turn softmax on and watch the two routes stop agreeing, because softmax's shared denominator ties every weight to every other score.

    07Feb 2021

    The delta rule (origin)

    Schlag, Irie, Schmidhuber (IDSIA / USI-SUPSI) — Linear Transformers Are Secretly Fast Weight Programmers, arXiv:2102.11174, ICML 2021

    Correction worth flagging: the delta rule is often attributed to the 2024 "DeltaNet" paper. That paper (below, order 17) is a parallel-training algorithm for this exact recurrence — the mechanism itself is three years older.
    Problem

    Linear attention's write rule is purely additive: S = S + kᵢvᵢᵀ. Writing a new association never corrects an old one — it just piles on top, so old and new associations can interfere and corrupt each other inside the same fixed-size state.

    Fixed

    Reframe the linear-attention state as a "fast weight" associative memory (echoing 1990s fast-weight-programmer nets), and replace the additive write with a delta-rule-style update: read what the memory currently returns for this key, compute the gap to what it should return, and write only that correction.

    Cost

    The corrective recurrence is inherently sequential at this point — computed one step at a time, with no way (yet) to parallelize it across the sequence for fast GPU training. That gap is exactly what the 2024 DeltaNet paper solves.

    When to choose it

    The right lens whenever "the model needs to overwrite/correct what it remembers," not just accumulate more of it — this is the conceptual seed for every delta-rule-based recurrent model that follows.

    Interactive — read, compute the delta, write only the correction
    08Apr 2021

    RoPE — Rotary Position Embedding

    Su, Lu, Pan, Murtadha, Wen, Liu (Zhuiyi Technology) — RoFormer: Enhanced Transformer with Rotary Position Embedding, arXiv:2104.09864

    Problem

    Neither sinusoidal nor learned absolute PE puts position directly into the query-key comparison — and prior relative-position schemes (Shaw et al., T5's relative bias) required modifying the attention computation itself, adding real parameters and compute.

    Fixed

    Rotate each query/key vector by an angle proportional to its position, applied as a pre-multiplication before the dot product. The rotations are multiplicative, so in the dot product the absolute rotations cancel and only the difference — the relative distance — survives: R(iθ)q · R(jθ)k = q · R((j−i)θ)k.

    Cost

    The base frequency (10000) fixes how position resolution is spread across the head's dimensions. That fixed choice is exactly what later breaks down at very long context — motivating NTK-aware scaling and YaRN below.

    When to choose it

    The default choice for almost any modern decoder-only LLM today — relative-position-aware, no extra learned parameters, and compatible with linear-attention variants.

    Interactive — rotate a key and a query, watch the relative angle
    Click "shift both +10" — the relative angle stays identical because it only depends on distance.
    09Aug 2021

    ALiBi

    Press, Smith, Lewis (UW / FAIR) — Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation, arXiv:2108.12409, ICLR 2022

    Problem

    Models trained with sinusoidal or even RoPE positions degrade sharply once evaluated on sequences noticeably longer than they were trained on — the "train short, test long" setting.

    Fixed

    Don't add any position signal to the inputs at all. Instead, subtract a static, non-learned penalty m · distance directly from the pre-softmax attention score — a per-head slope m, geometrically spaced across heads. Closer tokens get less penalty; farther tokens get more.

    Cost

    The penalty grows linearly with distance forever — a strong, fixed recency bias baked into the mechanism. Tasks that genuinely need to weight far-away evidence as heavily as nearby evidence fight against this bias.

    When to choose it

    Length extrapolation is the priority and a recency prior is acceptable or even desirable — the paper's own result: trained at 1024, evaluated at 2048, matching a sinusoidal model actually trained at 2048, while training 11% faster and using 11% less memory.

    No dedicated widget here — contrast it directly against the RoPE widget above: RoPE encodes distance inside the query-key dot product and stays neutral about which distance is "better"; ALiBi penalizes distance directly in the score, on purpose.
    10May 2023

    Grouped-Query Attention (GQA)

    Ainslie, Lee-Thorp, de Jong, Zemlyanskiy, Lebrón, Sanghai (Google Research) — GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints, arXiv:2305.13245, EMNLP 2023

    Problem

    MQA's one-shared-head extreme saved the most memory but cost the most quality, and training a separate MQA model from scratch wasn't always practical.

    Fixed

    A tunable dial between MHA and MQA: split query heads into groups, each group sharing one K/V head. The paper also introduces "uptraining" — converting an existing MHA checkpoint into a GQA model using only about 5% of the original pretraining compute.

    Cost

    Still a trade-off, not a free lunch — quality drops somewhat as the number of KV groups shrinks, in exchange for cache savings and decoding speed closer to MQA.

    When to choose it

    The default today for most serving-oriented LLMs (Llama 2's larger sizes, Mistral, Falcon) — a strong practical baseline. But note what it doesn't fix: the cache still grows linearly with context length, just with a smaller slope.

    Interactive — drag KV heads from 1 (MQA) to 8 (MHA)
    Try the KV-cache calculator further down this page — GQA lowers the slope of the cache-vs-context line, but the line still climbs.
    11 · bonusJun 2023

    Position Interpolation

    Chen, Wong, Chen, Tian (Meta) — Extending Context Window of Large Language Models via Positional Interpolation, arXiv:2306.15595 — not covered in the original lecture, added here because it's the direct predecessor to NTK-aware scaling and YaRN below and the timeline doesn't make sense without it.

    Problem

    A RoPE model trained at, say, 4K tokens produces garbage rotation angles once you simply evaluate it at 32K positions — the model never saw those angles during training.

    Fixed

    Instead of extrapolating to unseen positions, linearly compress every position index by the extension factor before computing the rotation — position 32,000 gets treated the way position 4,000 would have been. Every RoPE dimension is scaled by the same uniform factor.

    Cost

    Uniform compression squeezes the high-frequency dimensions just as hard as the low-frequency ones — and high-frequency dimensions are what encode fine-grained local position. Compress those too much and nearby-token discrimination degrades.

    When to choose it

    Simple to implement and a real improvement over naive extrapolation — but superseded within days by the community's NTK-aware idea below, which compresses non-uniformly instead.

    Interactive — how much rotary resolution survives at each extension factor
    Position Interpolation compresses every dimension by the same amount — notice the flat line across all dimensions.
    12~Jun 30, 2023

    NTK-aware RoPE scaling

    u/bloc97, r/LocalLLaMA — "NTK-Aware Scaled RoPE Allows LLaMA Models to Have Extended (8k+) Context Size Without Any Fine-Tuning and Minimal Perplexity Degradation". Not a peer-reviewed paper — a community post, with closely related independent work by kaiokendev the same month. The exact posting day is secondary-sourced (Reddit's own metadata wasn't directly fetchable); treat late June 2023 as approximate.

    Problem

    Position Interpolation's uniform compression damages high-frequency (fine local position) dimensions more than necessary.

    Fixed

    Relate the problem to Neural Tangent Kernel theory and scale dimensions non-uniformly: compress the low-frequency (long-range) dimensions more, and leave the high-frequency (local) dimensions closer to untouched.

    Cost

    Purely heuristic at the time — no formal error bound, no peer review, validated informally through perplexity numbers posted in the thread. Required manual tuning per model.

    When to choose it

    A genuine improvement over linear interpolation with no fine-tuning required — but treat it as a community finding to build on, not a rigorously validated method on its own; that formalization is exactly what YaRN does next.

    Interactive — same widget, locked to NTK-aware's non-uniform curve
    High-frequency (local) dimensions on the right stay closer to fully preserved; low-frequency (long-range) dimensions on the left absorb most of the compression.
    13Aug 2023

    YaRN

    Peng, Quesnelle, Fan, Shippole — YaRN: Efficient Context Window Extension of Large Language Models, arXiv:2309.00071, ICLR 2024 ("Yet another RoPE extensioN")

    Problem

    Both linear interpolation and the informal NTK-aware idea either needed substantial fine-tuning or left a real performance gap versus a natively-trained-long model.

    Fixed

    Formalizes "NTK-by-parts" — a refined, published version of bloc97's non-uniform interpolation — and adds a correction to the attention "temperature," fixing a softmax-entropy mismatch that interpolation introduces on its own.

    Cost

    One more hyperparameter (the temperature correction) to get right, and it still benefits from — though needs much less of — fine-tuning at the target length. Validated primarily on LLaMA-family RoPE models.

    When to choose it

    Extending an existing RoPE model's context cheaply: the paper reports comparable results to Position Interpolation with roughly 10× fewer tokens and 2.5× fewer training steps.

    Interactive — same widget, locked to YaRN's refined curve
    The illustrative quality bar below the curve is deliberately the least-degraded of the three modes at the same extension factor — that's the point of comparing all three at equal settings.
    14Sep–Oct 2023

    Sliding window attention — the decoder application: Mistral 7B

    Mistral AI — official blog announcement (Sep 27, 2023); paper: Jiang et al., Mistral 7B, arXiv:2310.06825 (Oct 10, 2023)

    Problem

    By 2023, decoder-only LLMs serving long conversations needed a KV cache that stops growing — Longformer's mechanism existed, but not yet wired into causal, KV-cached autoregressive generation.

    Fixed

    Each layer attends only to the previous 4,096 tokens. The KV cache becomes a fixed-size rotating buffer instead of a list that grows with every generated token — O(window · seq_len) compute, bounded memory.

    Cost

    Same information-loss trade as Longformer's origin: anything outside the window is invisible to that layer directly. Without something like attention sinks (next section), evicting the very first tokens can destabilize generation quality.

    When to choose it

    Serving long or streaming conversations where a bounded, predictable memory footprint matters more than exact access to the entire history.

    The dim outlined dots to the left of the window are already evicted from the cache — gone, not just unattended-to this step.
    15Sep 2023

    Attention sinks / StreamingLLM

    Xiao, Tian, Chen, Han, Lewis (MIT / Meta AI / CMU / NVIDIA) — Efficient Streaming Language Models with Attention Sinks, arXiv:2309.17453, ICLR 2024

    Problem

    A naive fixed-size sliding-window cache (like Mistral's) collapses in quality once the very first few tokens slide out of the window — even though the total sequence length is fine. The paper traces this to softmax: weights must sum to 1 across attended tokens, so the model needs somewhere to "dump" attention it doesn't want to allocate elsewhere, and under a causal mask the earliest tokens are visible to (and trainable as a target by) nearly every later position.

    Fixed

    Always keep the KV of a small number of initial "sink" tokens permanently cached — often just 4 — alongside the normal sliding window. This restores generation stability for streaming/effectively-infinite-length generation, with no fine-tuning required.

    Cost

    It's a stability fix, not a way to recover true long-range recall — content evicted from the sliding window is still gone. A small constant memory overhead (a few extra cached tokens) is the price.

    When to choose it

    Any deployment already using a bounded sliding-window KV cache for long or streaming generation — this is close to a strict improvement at near-zero extra cost.

    Interactive — evict the sinks and watch stability drop
    16May 2024

    Multi-head Latent Attention (MLA)

    DeepSeek-AI — DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model, arXiv:2405.04434

    Problem

    The DeepSeek-V2 paper states it directly: GQA and MQA reduce the KV cache, but their performance "does not match MHA." Fewer stored copies costs quality.

    Fixed

    A mechanistically different idea, not a rebrand of GQA: perform low-rank joint compression of keys and values together into one small latent vector per token. At attention time, the latent is expanded back out into full-size K and V. What's cached is only the small latent, not fewer copies of full-size vectors.

    Cost

    Added architectural complexity — extra up/down-projection matrices, and RoPE needs a decoupled handling scheme since rotation doesn't commute cleanly with the compression. More moving parts than "just share some heads."

    When to choose it

    When you want GQA-or-better cache savings without GQA's quality hit — the paper reports MLA matching or beating full MHA quality at a cache footprint comparable to roughly 2.25-group GQA.

    Interactive — fewer copies (GQA/MQA) vs. joint compression (MLA)
    17Jun 2024

    DeltaNet — parallelizing the delta rule

    Yang, Wang, Zhang, Shen, Kim — Parallelizing Linear Transformers with the Delta Rule over Sequence Length, arXiv:2406.06484, NeurIPS 2024

    Problem

    Schlag et al.'s 2021 delta-rule recurrence (order 07 above) is inherently sequential — it couldn't be parallelized across the sequence dimension, making it impractical to train at real scale on GPUs/TPUs.

    Fixed

    A hardware-efficient, chunk-parallel training algorithm using a memory-efficient Householder-matrix-product representation of the same recurrence — the delta rule's math is unchanged, but it can now be trained fast at scale. Scaled to 1.3B parameters / 100B tokens, beating Mamba and GLA at the time.

    Cost

    Algorithmic complexity — the chunked WY/Householder representation is intricate machinery compared to the conceptually simple original recurrence. Still a bounded-state recurrent model: recall is limited by the state's fixed size.

    When to choose it

    Whenever you want the delta rule's correction behavior at production training scale — this, not Schlag et al., is what people mean today when they say "DeltaNet" in most model cards.

    Interactive — same correction math, now trainable in parallel at scale
    18Dec 2024

    Gated DeltaNet

    Yang, Kautz, Hatamizadeh (NVIDIA) — Gated Delta Networks: Improving Mamba2 with Delta Rule, arXiv:2412.06464, ICLR 2025

    Problem

    The delta rule alone gives precise, targeted corrections but no efficient way to do wholesale forgetting — clearing out stale state that's no longer useful, which long-context tasks need. Mamba2-style gating does fast coarse forgetting but no targeted correction.

    Fixed

    Combine both in one recurrence: a data-dependent decay gate α that can erase state quickly, plus a write-strength β governing the delta-rule-style correction on top of what survives the decay.

    Cost

    Another set of learned gating parameters and another axis of complexity. Still a finite-state recurrent model underneath — gating helps manage that finite state, it doesn't remove the limit.

    When to choose it

    Long-context recurrent-state models where stale information genuinely needs to be forgotten, not just diluted by new writes — this is the D-layer building block LightningLM (last section) uses.

    Interactive — decay gate applied before the correction is written
    19Feb 2025

    Native Sparse Attention (NSA)

    DeepSeek-AI, Peking University, University of Washington — Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention, arXiv:2502.11089, ACL 2025

    Problem

    Most prior sparse-attention schemes were bolted onto an already-trained dense model, or used sparsity patterns not aligned with how GPU kernels actually execute — leaving real speedups on the table.

    Fixed

    Three parallel branches per query, trained end-to-end from scratch: coarse-grained compressed attention over blocks, fine-grained selected attention over the top-scoring blocks, and a sliding-window local branch — all designed to be hardware-aligned, not retrofitted.

    Cost

    Compression genuinely loses token-level detail (one summary now speaks for several tokens), and block selection can miss a relevant block if the summary undersells it. Being "natively trainable" also means you can't simply retrofit it onto an existing dense checkpoint.

    When to choose it

    Training a new long-context model from scratch where hardware efficiency at training time matters as much as inference-time savings.

    Interactive — every block is scored cheaply, only the top-k get full attention
    20Sep 2025

    DeepSeek Sparse Attention (DSA)

    DeepSeek-AI — DeepSeek-V3.2-Exp release notes, built via continued training on top of DeepSeek-V3.1-Terminus (Sep 29, 2025)

    Problem

    Even with NSA's design, deciding which blocks deserve expensive attention still needs to be cheap — scoring every block with the same cost as attending to it defeats the purpose.

    Fixed

    A small, cheap "lightning indexer" — a low-rank scoring module — ranks every block's relevance to the current query. A token/block selector then picks only the top-k highest-ranked blocks for the expensive attention read. Same core idea as NSA's selected-attention branch, shipped as a production model refinement.

    Cost

    The indexer's ranking is itself an approximation — a block the indexer underrates is a block the model never gets to read in full, regardless of how relevant it actually was.

    When to choose it

    Serving a very long context cheaply when you already have (or can train) a good cheap relevance signal — the indexer only has to be good enough to rank, not attend.

    Interactive — same top-k mechanism, DSA's production framing
    21Dec 2025

    DroPE

    Gelberg, Eguchi, Akiba, Cetin (Sakana AI) — DroPE: Extending the Context of Pretrained LLMs by Dropping Their Positional Embeddings, arXiv:2512.12167

    Problem

    RoPE's rotation formula can be evaluated at any position — that doesn't mean the model behaves well there. A model trained only up to 8K tokens has never learned what rotation patterns beyond that mean, even though the function is happy to keep producing numbers.

    Fixed

    Pretrain normally with RoPE, as usual. Then, rather than scaling or interpolating the rotation, drop the positional embeddings entirely and run a brief recalibration phase at the original training context length. This restores the model's original in-context perplexity while substantially improving how well it generalizes to longer lengths — without a full long-context fine-tuning run.

    Cost

    Validated by Sakana on standard RoPE transformers up to 7B parameters — it's a recent technique, and its behavior at much larger, architecturally different models (hybrid recurrent + sparse-attention stacks) is a live open question, not yet independently established at that scale.

    When to choose it

    Extending an already-trained RoPE model's usable context without committing to a full long-context training run.

    LightningLM 0.1V — DroPE applied at 120B scale

    Shravan (The School of AI) — Reversible Foundations: Training a 120B Sparse MoE through State-Preserving Scaling, arXiv:2606.07404

    Naming correction: this is not a frontier-lab release. It's a 120B-parameter sparse MoE built by The School of AI's ERA V4 cohort — a training program, not a company. The model's actual version string is 0.1V; "V4" refers to the cohort number, not a model version. And DroPE was not invented here — it's Sakana AI's technique (above), applied downstream at a much larger scale than Sakana's own published experiments covered.

    The architecture repeats an eight-layer motif, D D D G D D D G, where D is a Gated DeltaNet-style fixed-state layer and G is a sparse-attention layer — six D's compressing history cheaply, two G's giving the model a chance to read selected earlier tokens directly. A "Memory Stream" carries one fixed-size, model-width summary vector across chunk boundaries (written with a stop-gradient, read with a small learned gate), so state from an earlier chunk isn't simply discarded. Positional recalibration via DroPE was applied before the final annealing stage of training.
